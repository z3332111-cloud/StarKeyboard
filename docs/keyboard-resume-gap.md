# 從背景返回後，鍵盤上方多出空隙：排查紀錄

## 目前結論（v0.10.5）

- 原本柔化背景上下緣的遮罩已拿掉：背景填滿鍵盤，不會再自己多露出一段底板。
- 從背景返回時重新要求高度（v0.10.4）已移除：鍵盤自身尺寸不變，收起再開也不會恢復，這招對不上症狀。
- 宿主多出的頂部間距，目前沒有找到 extension 能蓋掉的方法；要等真機診斷紀錄確認。
- 實驗開關和小狐狸的山景標題已由 PR #5 移除（v0.10.6）；小狐狸也會出現這段空隙，不是線索。

## 已知重現條件

- 使用者回報 iOS 27.2，Discord 和其他 App 都會發生。
- 開啟鍵盤、切到其他 App、返回後，上方偶爾露出一段圓角底板。
- 收起再開啟鍵盤不能恢復；把宿主 App 從多工畫面關掉後再開可恢復。
- 截圖中的按鍵區位置看起來相近，上方輸入框與圓角背景不同；這是視覺線索，尚非真機座標量測。

## 最強的外部線索：宿主端增加頂部間距

[Apple 開發者論壇 thread 843093](https://developer.apple.com/forums/thread/843093) 的第一手回報重現了相同切換流程：extension 尺寸及安全區不變，宿主容器增加 17pt 頂部間距。討論中也有 iOS 27.2 RC 的回報。這是開發者量測，並非 Apple 官方根因確認，也尚未證明本機個案完全相同。

因此，目前優先假設是宿主／系統的間距狀態，而非鍵盤自身高度。延伸測試可在問題出現時，手動切到 Apple Emoji 鍵盤再切回，與從 Apple 英文鍵盤切回的結果比較；這是該討論提出的重現線索，不保證能恢復。

不使用固定扣除 17pt、向上移動內容或修改私有容器來補償，因為正常狀態可能沒有這段間距。診斷若顯示 extension 幾何完全不變，也符合上述假設；要直接量到宿主的 keyboard frame，仍須在可控制的測試宿主 App 或 Xcode 取得資料，不能期待 extension 一定能收到宿主通知。

## 程式碼查核結果

- 一般主題的 `topBar` 從 `folderBoxHeight` 開始；未開啟編輯框時為 0。沒有另外插入上方間距。
- `backdropView` 每次 layout 都填滿 `view.bounds`，沒有漸淡遮罩。
- 高度由上下貼齊 root view 的 `heightRuler` 及 priority 999 的高度約束決定。
- 原本 `viewDidAppear` 就會停用、重建高度約束。這次保留既有行為，記錄前後幾何資料，以免同時變更行為而失去比較基準。
- 橫向判斷使用 `UIScreen.main.bounds`，也是值得比對的輸入，但目前沒有證據表示直向重現的問題由此引起。
- 沒有發現能直接證明根因的前景恢復處理；目前不能宣稱已修好，也不能斷定為系統 bug。

Apple 說明 [`allowsSelfSizing`](https://developer.apple.com/documentation/uikit/uiinputview/allowsselfsizing) 使用 input view 的 Auto Layout fitting size。這支持檢查「要求高度」與「實際尺寸」是否一致，並不表示再設定一次高度就能解決。

## 本次加入的診斷

鍵盤 ⚙️ 設定 →「鍵盤上方多出空隙？」提供開始、複製與停止。

1. 安裝含診斷功能的 IPA。先完全關閉再開啟要測試的 App，確認鍵盤正常。
2. 開始版面診斷（會返回鍵盤），不調整主題、方向或高度。
3. 保留鍵盤開啟，切到其他 App 再返回，重現空隙。
4. **先複製版面紀錄，再完全關閉 App**，避免鍵盤程序結束而失去紀錄。複製需完整取用，剪貼簿內容 5 分鐘後到期且不跨裝置同步。
5. 可另外記錄收起／重開鍵盤後的狀態；不同 App 各做一份。將紀錄與對應正常／異常截圖一併比對。

只記錄尺寸、位置、安全區域、約束要求、window／controller 識別與生命週期事件，不讀取聊天、按鍵、剪貼簿或宿主 App 身分。預設關閉，不寫檔、不上傳，保留起始快照與最近 160 筆。停止後保留本次資料供複製；重新開始或鍵盤程序結束會清除。

診斷不呼叫 `layoutIfNeeded`、fitting size、延遲重設高度、鍵盤 reload 或修改系統 view。通知只代表 extension 實際收到的事件，不能假定宿主的前背景事件必定傳入 extension。

## 如何判讀

| 比對項目 | 能縮小的範圍 |
| --- | --- |
| requested 高度不變，但 actual／delta 改變 | 先查 Auto Layout 高度協商與系統分配的內容尺寸 |
| root 尺寸不變，topBar／content 在 root 內的位置改變 | 查自己的編輯框、主題標頭與排版狀態 |
| root 內的幾何不變，但 inWindow／inScreen 改變 | 查外層位置與 window／scene 轉換 |
| 可觀察幾何都不變，截圖仍多出底板 | 更偏向 extension 無法觀察的宿主／系統背景，需再做最小 extension 重現與系統回報 |

`ancestor[n]` 只是沿公開 `superview` 屬性取得的幾何；不是已辨識的系統鍵盤底板，也不保證能跨越程序看到實際宿主容器。安全區域非零也不能單獨證明根因。

- 真機正常／異常診斷資料：待取得。這是診斷版本，尚非根因修復。
